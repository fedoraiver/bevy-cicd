# ADR 0001：共享调度导出启动器

## 状态

2026-11-22 采用。声明 App 构造函数的项目使用共享启动器。旧入口继续兼容此前的调用方修订。

## 背景

架构站点将编译器事实与真实 Bevy App 的调度绑定。此前项目通过自身二进制的命令行入口和可选 Cargo 依赖启用导出，项目锁文件也包含导出所需的依赖。

## 决策

- 项目通过 `package.metadata.bevy-architecture.app-factory = "build_app"` 声明库根的公开无参数 App 构造函数。共享分析器在自己的构建目录生成启动器，使用路径依赖调用同一套 App 装配。
- 启动器在本机目标上启用 Bevy 调试信息。其锁文件以项目锁定版本为基础，解析后核对项目依赖的版本和来源。导出器使用启动器锁文件记录依赖版本，以未修改的项目 Cargo 文件和源码计算来源指纹。
- 从一轮 Cargo 构建获取项目库的编译器事实和启动器二进制。运行该二进制完成插件装配和调度导出，将二进制与快照哈希写入提取证据。现有调度、模型和 Pages 产物流程继续使用这些证据。

## 备选方案与取舍

可以将命令行处理移入共享库，并继续让应用二进制承担导出。这保留了同一个应用可执行文件，但要求每个项目配置导出 feature 和依赖。专用启动器让项目只维护 App 装配接口，需要单独解析并校验锁文件以及区分项目库和启动器的编译证据。

## 验证要求

覆盖新旧入口、构造函数缺失、依赖版本变化、项目文件完整性和真实调度注册。验证启动器在读取主应用和子应用调度时不执行 Startup 或渲染循环。实际项目的架构构建须通过调度和模型校验，发布证明须对应同一次构建的提交。

## 已完成验证

原生启动器和旧入口的回归通过。新入口的夹具验证了实际调度、实体模板、启动器和快照哈希、热运行复用，以及项目清单和锁文件完整性。缺失构造函数的编译检查和导出依赖版本不符的回归均产生预期错误。

## 未决问题

迁移保留旧入口供历史提交和现有调用方使用。根据调用方迁移进度另行评估停用旧入口。
